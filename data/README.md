# data/

运行时的解读数据库目录，以只读方式挂载进容器（`./data:/data:ro`）。

## 这里应该有什么

| 文件 | 是否进 git | 说明 |
|---|---|---|
| `interp.db` | ❌（662 MB，超 GitHub 限制） | 674,976 张命盘 × 13 维的解读库 |
| `interp.db.sha256` | ✅ | 当前代码期望的数据集校验值 |

`deploy.sh` 启动前会校验 `interp.db` 的 SHA256。662 MB 的文件经上传、解压后
有可能损坏，而坏库的表现只是「查不到盘」，不容易发现。

## 怎么拿到 interp.db

见仓库根目录 [README](../README.md) 的「数据集不在这个仓库里」一节：
用安装包里的现成文件、从 Release 下载，或自己从原始数据编译。

## 关于只读挂载

数据库以 `delete` 日志模式编译（不是 WAL），因此可以安全地只读挂载。
如果换成 WAL 模式，`:ro` 挂载会因为无法创建 `-shm` 文件而打不开——
要换的话得同时改 `docker-compose.yml` 的挂载方式。
